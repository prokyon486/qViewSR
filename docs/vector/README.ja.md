# ベクター変換

静止画から、色の塗りと主線を分けたSVGを作成し、指定倍率のPNGとして保存できます。
元画像ファイルは変更しません。変換はCPUで行い、NCS／NCS2による超解像とは独立した処理です。

初めて使用する環境では、リポジトリのルートで`python3 tools/vector/setup_vector.py`を実行して依存ツールを準備します。
取得するバージョン、ライセンス、コマンドラインでの検証方法は[実行環境の説明](../../tools/vector/README.md)を参照してください。

## 使い方

1. 変換したい静止画を開き、「ベクター」→「塗りSVG＋主線SVGを調整…」、または `Ctrl+Shift+V` で調整ウィンドウを開きます。右クリックのメニューにも同じ項目があります。
2. 「生成・更新」を押して変換します。入力は、表示倍率や超解像結果に関係なく無加工の元画像です。
3. 塗りと主線の設定を調整します。生成後の設定変更は自動反映されます。
4. 「変換結果を表示」で変換結果と元画像を比較します。通常の拡大・縮小と画像移動も利用できます。
5. 「SVG保存」でベクターデータを、「PNG保存」で指定倍率の画像を保存します。

プレビューはSVGのまま保持し、ズームや移動に合わせて画面に見える範囲を描き直します。
拡大しても固定サイズの画像の画素を引き伸ばさず、曲線と塗りの輪郭を画面解像度で描画します。
回転・反転、HiDPI表示、画面ICCにも対応します。線や塗りの形そのものはベクター化時の設定で決まります。

調整ウィンドウを閉じても、その画像の変換結果と設定は保持します。別の画像を開くと、前の画像の結果は破棄します。
調整ウィンドウはメイン画面とは別に移動できます。別のモニターへ置くこともでき、位置と設定を次回起動時に復元します。
設定欄は縦にスクロールでき、生成・中止・保存ボタンは下部に残ります。
全画面中は調整ウィンドウを隠し、全画面を解除すると元の表示状態へ戻します。
変換中は「中止」で処理を停止できます。元画像を超解像する操作とベクター変換は別の処理です。

## 調整項目

| 項目 | 効果 |
|---|---|
| 主線の抽出方式 | 「暗い主線」は線の中心を拾います。「色の境界」は明るさだけでなくRGBの色差と透明部分のシルエットを拾い、ロゴや色面の輪郭に向いています。 |
| 主線の抽出強度 | 弱い設定でははっきりした線を中心に抽出し、強い設定では薄い線や細部も拾います。強くすると模様やノイズも線になりやすくなります。 |
| 線抽出の隙間補正 | 暗い主線の中の細い隙間を埋め、梯子状の分岐を抑えます。OFF／1px／2px。初期値OFF、色の境界方式には適用しません。 |
| 曲線の細かさ | 細かい設定では元の形へ近づけ、簡略化する設定では曲線の数を減らします。簡略化しすぎると目・口・指などの形が変わります。 |
| 主線を補正 | ほぼ直線の区間を直線に、閉じた円・楕円に近い輪郭を整った形に近似します。滑らかな区間は、少ない制御点のベジエ曲線にまとめます。初期値はOFFです。 |
| 円・楕円の許容誤差 | 元画像のピクセル単位で、揺らいだ閉輪郭を円・楕円に寄せる許容値を調整します。初期値2px。直線・曲線の補正誤差とは独立です。 |
| 主線を整理 | 短い孤立線と主線に直交する短い横枝を減らし、方向の揃った途切れをつなぎます。初期値OFF。形状補正とは別に切り替えられます。 |
| 短い線の基準長 | 孤立線はこの長さ未満を除去し、横枝の長さ判定にも使います。初期値6px。0で短線の除去を止めます。 |
| 途切れの接続距離 | 接続を試す端点間の最大距離。初期値4px。0で接続を止めます。方向が違う・候補が複数ある・他の線と交差する場合はつなぎません。 |
| 短い横枝の除去 | 滑らかな長い主線に対する短い横枝の除去強度。初期値50%。0で横枝の除去を止めます。 |
| 元線の弱化 | 塗りに残る元の線を近くの色で補間して弱めます。上に重ねる主線と元の線の二重化を調整する項目です。 |
| 主線の太さ・不透明度 | 抽出した主線の見え方を調整します。曲線の形は変えません。 |
| 受け渡し画像の倍率 | Ctrl＋ドラッグで他のアプリへ渡す画像を0.01〜8倍で作ります。既定は4倍です。大画像は1倍未満で縮小して渡せます。画面のベクター描画の滑らかさには影響しません。 |
| 主線の色 | 透明・白・黒・元画像から推定を選べます。透明は主線レイヤーを非表示にする指定で、塗りに残る元の線は消しません。 |
| 背景の色 | 透明・白・黒を選べます。透明にしても、塗りの白い部分は保持します。 |
| 塗りを表示・グレースケール化 | 塗りの表示と色を切り替えます。グレースケール化の対象は塗りだけで、主線の色は維持します。 |
| PNGの倍率 | 元画像に対する保存寸法を0.01〜8倍で指定します。SVGから指定寸法へ描画します。 |

％の項目は横スライダーで調整できます。主線の濃さと横枝の除去は1％刻み、元線を弱める量は5％刻みです。

元線の弱化は、元の塗りや消された部分を正確に復元する処理ではありません。
強くすると色がにじんだり、線が消えすぎたりするため、元画像と比較して調整してください。
主線を同時に太く・濃くすると、細部がつぶれる場合があります。

## 主線の抽出と整理

「暗い主線」は周囲より暗い細い部分を検出します。太い文字の外周、広い色面の段差、明るさが近く色だけ異なる境界には「色の境界」を試してください。
「色の境界」は細いインク線の両側も拾うため、暗い主線と合成せず切り替える方式です。白いロゴや白背景との境界を確認するときは「主線の色」を黒にすると見やすくなります。
透明ロゴでは不透明側の内側1pxの輪郭を拾います。透明画素に隠れているRGBや、画像の外枠は輪郭として追加しません。

暗い主線と薄い影の間に細い溝があると、トレースが二重の輪郭と短い横桟を作る場合があります。この場合は「線抽出の隙間補正」を1pxにして比較してください。抽出した二値領域を3×3（1px）または5×5（2px）で整えてからトレースします。
近接した別の線、細い文字の空白、小さな丸の穴まで結合する場合があります。通常はOFFとし、必要な画像で1pxから試してください。2pxが常によい結果になるわけではありません。この設定は抽出に影響するため、変更すると主線を再トレースします。塗りには適用しません。

「主線を整理」はトレース後・色付け前に実行します。孤立した短い開いた線、十分な支持長のある滑らかな主線にほぼ直交する短い枝を除去します。主線が複数片へ分かれている場合は、その方向の連続も確認します。
近くの端点は、接線方向が揃い、互いの接続先が一つに定まり、既存の線を横切らない場合にベジエ曲線で接続します。小さな隙間がある閉輪郭を閉じる場合もあります。
閉じた小さな記号、長い枝、曖昧な分岐、過密な領域は残します。ただし、短い線がノイズか文字・模様かは判断できません。OFFとの比較で必要な細部が消えていないか確認してください。
すべて元画像のピクセル単位です。拡大済み画像では、その倍率に合わせて基準長・接続距離を調整してください。強くするほど細部の欠落や意図しない接続の可能性も増えます。

## 主線の補正

「主線を補正」をONにすると、抽出した主線に幾何学的な近似を適用します。塗りは変更しません。
直線・曲線の補正は抽出後の線に対して元画像の約1ピクセル以内を基準とします。円・楕円には専用の許容誤差を使い、指定値と推定した短半径の5%の小さい方に制限します。
ピクセル階段や細かな揺れは近傍の方向を見て判定し、ノイズの折れだけで候補を除外しないようにしています。判断できない形はそのまま残します。
開いた線の端点、角、分岐点を保持し、途中で引き返す線や星形などを円へ置き換えないよう判定します。
円・楕円は閉じた輪郭が対象です。通常は4本の3次ベジエ曲線で表し、大きい形状では誤差を抑えるため分割数を増やします。

ON/OFFは「曲線の細かさ」「主線を整理」と独立しています。OFFでは形状補正前の主線へ戻ります。整理もOFFにすると抽出した元の線を復元できます。
補正前のトレース結果をキャッシュするため、同じ画像と抽出設定でON/OFFするだけならAutoTraceを再実行しません。
両方の結果が生成済みなら、入力画像の展開・色変換も省略して比較できます。
整理した線も別にキャッシュするため、円・楕円の許容誤差を変えても整理をやり直しません。パネルには除去・接続件数と直線・円・楕円・曲線簡略化の適用数を表示します。
これは形状の近似であり、物体や意図した輪郭を認識する処理ではありません。細部優先／標準／簡略化と組み合わせて確認してください。
元画像の色は補正後の区間から推定するため、区間をまとめた部分では色の切り替わりも変わる場合があります。

## 大きい入力画像

入力に対する400万画素・一辺4096px・圧縮ファイル128MiBの固定制限はありません。
1万ピクセルを超える画像も、縮小せず元の解像度でベクター化します。
入力の展開や処理に必要なメモリーを事前に見積もり、利用可能量が不足するときは理由を表示して止めます。
SVGは各層と合成結果それぞれ最大1GiBです。読み込み・合成前に、SVGバイト数の32倍＋64MiBが空きメモリーの70%以内かを確認します。
空きメモリー量を取得できない環境では、従来の64MiBまでとし、それを超える場合は理由を表示します。
画像の内容によって処理時間とSVGの複雑さは大きく変わります。大画像では中止するまで時間がかかる工程もあります。
元線弱化の繰り返し計算中は、進み具合を表示します。
入力準備中の「中止」も、色変換の終了時またはPNGの次の書き込み時に反映し、未完成の作業用画像は破棄します。

元線弱化の補間と、塗りの色領域から曲線を作る工程は、利用可能なCPUに応じて最大16スレッドで処理します。
小さい処理は直列のまま実行し、余分なスレッドを作りません。主線の色付けもまとめて計算し、細かな繰り返しの負担を減らしています。
色領域を統合する工程やAutoTraceの主線抽出など、直列で進む工程は残ります。その間はCPU全体の使用率が低くても処理を続けています。

16コアのThreadripper 2950Xで、6144×6144pxの実画像切り出しを使った元線弱化は、約215秒から約58秒になりました。出力画素は変更前と一致しています。
17984×21120pxの実画像では、塗りのトレース単体が約91秒、最大メモリー約18.6GiBでした。この時間には入力画像の準備・元線弱化・主線抽出・GUI描画は含みません。

大きい色領域で色集計が桁あふれしないよう、64ビット集計へ修正したVTracerを使用します。
既存の環境は `python3 tools/vector/setup_vector.py` で更新できます。旧版のままなら、変換前に更新方法を表示します。
修正内容と固定ソースからの再ビルド手順は [VTracerの大画像向け修正](../../tools/vector/patches/README.md) を参照してください。

画面操作用の補助画像は最大1600万画素・一辺8192pxに抑えますが、SVGの座標や形状を縮小するものではありません。
ズーム時は引き続き元のSVGを画面解像度で描画し、「実際のサイズ」は元画像の画素座標を基準にします。
Ctrl＋ドラッグでは、補助画像を流用せず、指定倍率の画像をSVGから作ります。
PNG／受け渡し画像には下記の出力上限があるため、必要に応じて1倍未満を指定してください。SVG保存にはこの画像化上限は適用されません。

長い輪郭を含む生成SVGは、LinuxではlibrsvgとCairoで描画します。Qt SVGの輪郭要素数の上限で表示が途中で切れるのを避け、保存するSVGの曲線・穴・描画順をそのまま使います。通常の短い輪郭はQtで描画します。
Ubuntuでは `librsvg2-2` と `libcairo2` が必要です。このPCには導入済みで、新しい環境の依存導入スクリプトにも含みます。利用できない環境では理由を表示し、輪郭が欠けた画像を保存しません。
代替描画へ渡すのは、この機能が生成した図形だけのSVGです。外部参照などを除外し、サイズと空きメモリーを検証したうえで大きいデータを読み込みます。描画エンジンが異なるため、境界のアンチエイリアシングには差が出る場合があります。

## 保存・色

SVGは塗りと主線をパスとして保持します。元のラスター画像をSVGへ埋め込む方式ではありません。
SVG対応の編集ソフトで、塗りと主線を個別に扱えます。
PNGはsRGBプロファイル付きで保存します。入力画像のICCを反映してsRGBへ変換し、
画面表示には既存の画面ICC設定を適用します。
SVGとPNGの保存には、ビュー上で行った90度単位の回転と左右・上下反転を反映します。
ズーム倍率や画面からはみ出した部分による切り抜きは保存結果へ反映せず、画像全体を保存します。
Ctrl＋左ドラッグでは、表示している変換結果を「受け渡し画像の倍率」で指定したPNGとして他のアプリへ渡せます。
画面のズーム倍率や表示範囲は、PNG保存・受け渡し画像の寸法や範囲へ影響しません。

SVGにした後の拡大は、元の画素を補間する通常の拡大とは異なり、曲線と領域を指定寸法へ描画する処理です。
ただし、変換時に失われた細部や元画像にない情報が復元されるわけではありません。

## 対象と制約

- 静止画を対象とします。GIFなどのアニメーションとGLBは対象外です。
- RGB画像と、完全透明／完全不透明だけの画像に対応します。中間の透明度を含む半透明画像は、透明部分の色や輪郭を正しく保持できないため、理由を表示して変換を止めます。
- 入力寸法による固定上限はありませんが、利用可能メモリー、画像デコーダー、変換ツールの処理可能範囲に依存します。SVGは各層・合成結果とも1GiBまでで、合成前には両層の合計サイズも確認します。
- 受け渡し画像とPNG出力は最大6400万画素、各辺32768ピクセルまでです。長い輪郭をCairoで描画する場合は各辺32767ピクセルまでです。倍率によって上限を超える場合は小さくしてください。
- 画面表示では見える範囲だけを画像化します。1回の描画が6400万画素または各辺32768ピクセルを超える特殊な表示環境や、メモリー不足時は、用意済みの画像を表示します。
- 線画・ロゴ・色分けが明瞭なイラストに向いています。写真、ぼかし、細かい質感、グラデーションは見え方が変わります。
- 主線抽出は髪・影・模様も線として拾うことがあります。抽出方式と強度、整理のON/OFFを比較してください。
- 「暗い主線」の抽出の近傍サイズは9×9画素です。元画像を大きく引き伸ばして太くなった線の中心など、抽出されない部分を幾何補正だけで復元することはできません。
- 主線色は元画像の近傍をサンプリングした色です。線に沿った連続的なグラデーションや筆圧の変化を再構成する処理ではありません。
- 細かい設定ほどSVGのパス数、処理時間、メモリー使用量が増えます。大きいSVGは他の編集ソフトでも表示に時間がかかる場合があります。
- 元の超解像機能は引き続き利用できます。ベクター変換でNCSを使う設定はありません。

すでに作成した超解像結果は、ベクター表示へ切り替えても保持します。
超解像を開始したり元画像／SR表示へ切り替えたりすると、ベクター結果の表示を解除します。
複数の処理結果を同時に重ねて表示する機能ではありません。

## 導入と検証

このPCでは必要な環境を導入済みです。別の環境では、リポジトリのルートで次を実行します。

```bash
python3 tools/vector/setup_vector.py
python3 tools/vector/setup_vector.py --check
```

PythonパッケージとAutoTraceは `.local` 内へ隔離します。詳しい依存・固定版・ライセンスは [workerの説明](../../tools/vector/README.md)を参照してください。

ローカル検証は次のコマンドで実行できます。GitHub CIは実行しません。

```bash
.local/vector-probe-venv/bin/python tools/vector/test_vector_worker.py
.local/vector-probe-venv/bin/python tools/vector/test_line_correction.py
.local/vector-probe-venv/bin/python tools/vector/test_line_cleanup.py
.local/vector-probe-venv/bin/python tools/vector/test_edge_extraction.py
.local/vector-probe-venv/bin/python tools/vector/test_mask_cleanup.py
.local/vector-probe-venv/bin/python tools/vector/test_color_paths.py
QT_QPA_PLATFORM=offscreen build/gui/tests/vectortests
QT_QPA_PLATFORM=offscreen build/gui/tests/srtests externalVectorPreviewLifecycle vectorRejectsFrozenAnimation
```

大画像の実処理は通常テストから分離し、対象ファイルを明示して実行できます。この検証だけはQt Test側の期限を1時間に延ばします。

```bash
QT_QPA_PLATFORM=offscreen \
QVIEWSR_TEST_LARGE_VECTOR_IMAGE=/absolute/path/to/large.png \
ARTIFACTS=/absolute/path/to/local-results \
build/gui/tests/vectortests largeSquareImage
```

## 使用している処理

主線は明度差による抽出とAutoTraceの中心線トレース、塗りはVTracerのカラー領域トレースを使用します。
SVGの描画にはQt SVGと、長い輪郭用のlibrsvg／Cairoを使用します。生成後の線幅や不透明度の変更では既存のパスを再利用します。

関連する公式資料: [AutoTrace](https://github.com/autotrace/autotrace)、
[VTracer](https://github.com/visioncortex/vtracer)、[Qt SVG](https://doc.qt.io/qt-6/qsvgrenderer.html)、
[librsvgの描画API](https://gnome.pages.gitlab.gnome.org/librsvg/Rsvg-2.0/method.Handle.render_document.html)、
[Cairoの画像サーフェス](https://www.cairographics.org/manual/cairo-Image-Surfaces.html)。
